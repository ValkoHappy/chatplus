# Как добавить страницу

Главное правило: новые публичные страницы создаются как `Page` в Strapi. Техническое имя этой модели в коде - `page_v2`, но в интерфейсе редактору достаточно искать `Page`.

Для редактора приоритетный способ - сначала создать `Generation Job`, получить AI-черновик `Page`, проверить preview и только потом публиковать. Ручное создание `Page` остается запасным способом, если нужна маленькая простая страница или точечная правка.

Если вы не разработчик, вам нужны только разделы “Вариант 0” и “Вариант 1”. Команды ниже относятся к технической проверке оператором.

Редактор не должен создавать новую страницу через код, VPS, Docker или Git. Для обычной страницы достаточно Strapi:

```text
Content Manager -> Page -> Create new entry
```

## Вариант 0. Новая страница через нейросеть

Используйте этот вариант для большинства новых промо, брендовых и ресурсных страниц.

### Шаги в Strapi

1. Откройте `Content Manager -> Generation Job`.
2. Нажмите `Create new entry`.
3. Заполните:
   - `title` - понятное название задачи.
   - `job_type = manual_request`.
   - `status = queued`.
   - `target_blueprint` - `campaign`, `brand` или `resource`.
   - `request_prompt` - что именно нужно сделать.
   - `requested_by` - кто поставил задачу.
4. Если нужно, выберите категории-контекст:
   - `target_channels`;
   - `target_industries`;
   - `target_integrations`;
   - `target_solutions`;
   - `target_features`;
   - `target_business_types`;
   - `target_competitors`.
5. Если в relation-поле видно только несколько вариантов, начните печатать название внутри поля. Strapi подгрузит остальные варианты поиском.
6. Не нажимайте `Create a relation`, если не уверены, что надо создать новую сущность. Обычно лучше оставить поле пустым и написать контекст в `request_prompt`.
7. После запуска генерации откройте связанную `Page`.
8. Посмотрите закрытый Astro preview.
9. Если результат хороший, поставьте `editorial_status = approved` и нажмите `Publish`.
10. Если результат плохой, не публикуйте. Создайте новый `Generation Job`, выберите эту `Page` в `target_page` и напишите prompt на доработку.

Пример prompt:

```text
Сделай черновик страницы про Telegram для онлайн-школ.
Цель: показать, как CHATPLUS помогает отвечать ученикам и собирать заявки.
Нужны блоки hero, преимущества, шаги запуска, FAQ и финальный CTA на /demo.
Пиши по-русски, без выдуманных цифр и без обещаний, которые нельзя проверить.
```

## Вариант 1. Новая страница без старого URL

Используйте этот вариант для новых ручных маршрутов, если AI не подходит или нужна точечная ручная сборка.

### Шаги в Strapi

1. Откройте `Content Manager -> Page`.
2. Нажмите `Create new entry`.
3. Заполните:
   - `title` — внутреннее название.
   - `slug` — короткий ключ, например `spring-promo`.
   - `route_path` — публичный адрес, например `/spring-promo`.
   - `page_kind` — тип страницы.
   - `blueprint` — стартовая схема страницы.
   - `seo_title` — title для поисковиков.
   - `seo_description` — description для поисковиков.
4. Соберите страницу из блоков в `sections`.
5. Заполните настройки меню и sitemap, если они нужны.
6. Поставьте `editorial_status = approved`.
7. Нажмите `Publish`.

Новый route не требует отдельного `.astro` файла. Его подхватит общий page-layer после публикации и rebuild/deploy текущего production flow.

Для новой native-страницы не включайте `migration_ready`: она станет видимой после `Publish` и `editorial_status = approved`. `migration_ready` нужен только для старых URL, где мы защищаем старый макет.

Если после публикации страница не появилась сразу, не заходите на сервер. Передайте техническому оператору `route_path`, например `/spring-promo`, и попросите проверить rebuild/deploy.

## Вариант 2. Перенос существующей старой страницы

Используйте этот вариант, если URL уже существует: `/pricing`, `/partnership`, `/features`, `/compare/respond-io` и похожие.

### Почему тут осторожнее

У старой страницы уже есть свой макет. Поэтому одной публикации в Strapi недостаточно. Сначала нужно убедиться, что новая запись сохранила:

- hero;
- CTA;
- таблицы;
- карточки;
- FAQ;
- внутренние ссылки;
- SEO;
- старую family-структуру.

### Правило показа старого route

Старая страница переключается на `page_v2` только если одновременно выполнено:

- запись опубликована;
- `editorial_status = approved`;
- `migration_ready = true`;
- `parity_status = approved`.

Если хотя бы одно условие не выполнено, сайт показывает старый fallback.

## Вариант 3. Каталоговая или SEO-страница

Каталожные страницы тоже материализуются в `page_v2`, но факты остаются в сущностях:

- `channel`;
- `industry`;
- `integration`;
- `solution`;
- `feature`;
- `business_type`;
- `competitor`.

Это значит:

- сущность хранит факты;
- `page_v2` хранит публичную страницу, блоки, SEO, ссылки и route.

Если нужно добавить новый канал, отрасль, интеграцию, сценарий, функцию, тип бизнеса или конкурента, создайте запись в соответствующем справочнике Strapi или дайте AI предложить ее в `run_report.proposed_entities`. AI-предложения не применяются молча: задача получает `status = needs_entity_review`, оператор проверяет дубли/slug/описание и подтверждает создание черновика. Справочник сам по себе не заменяет публичную страницу и не отменяет проверку preview. Подробно: [Справочники: каналы, отрасли, интеграции и страницы по ним](entity-catalog-editor-workflow.md).

## Как выбрать `page_kind`

| Если нужна страница | Используйте |
| --- | --- |
| Обычный лендинг | `landing` |
| Промо или спецстраница | `campaign` |
| Страница компании, медиа, команды | `brand` |
| Документация, блог, помощь | `resource` |
| Корень каталога | `directory` |
| Карточка сущности | `entity_detail` |
| Пересечение сущностей | `entity_intersection` |
| Сравнение | `comparison` |
| Служебная страница | `system` |

## Минимальный набор перед публикацией

Перед `Publish` проверьте:

- `route_path` заполнен и начинается с `/`;
- `seo_title` заполнен;
- `seo_description` заполнен;
- есть хотя бы один содержательный блок в `sections`;
- CTA ведет на рабочий URL;
- internal links не пустые, если блок добавлен;
- `show_in_sitemap` включен только для страниц, которые нужно индексировать.

## Что делать после создания

Для редактора:

1. Откройте новый URL на публичном сайте.
2. Проверьте заголовок, CTA, ссылки, FAQ, SEO-смысл и отсутствие тестового текста.
3. Если страница не открылась или выглядит плохо, передайте техническому оператору `route_path`.

Локально или на сервере технический оператор должен проверить:

```powershell
npm.cmd --prefix portal run build
npm.cmd run page-v2:data-quality -- --problems --json
npm.cmd run page-v2:rendered-coverage -- --problems --json
```

Если отчеты пустые, страница не потеряла обязательный контент.

## Что нельзя делать

- Не создавайте новые ручные страницы в legacy-моделях.
- Не включайте `migration_ready` у старого маршрута без проверки макета.
- Не удаляйте старый `.astro` wrapper на этом этапе.
- Не переносите страницу в неподходящий generic-блок, если старый макет требует отдельный блок или variant.
