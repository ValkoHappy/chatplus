# Как добавить страницу

Главное правило: новые публичные страницы создаются как `Page` в Strapi. Техническое имя этой модели в коде - `page_v2`, но в интерфейсе редактору достаточно искать `Page`.

Для редактора приоритетный способ - сначала создать или подготовить `Page` с правильным макетом, затем создать `Generation Job`, чтобы AI заполнил текст в этой выбранной `Page`. После этого редактор проверяет preview и только потом публикует.

Важно: AI больше не создает свободную страницу без выбранной `target_page`. Сначала нужна `Page` с правильным каркасом и макетом, затем `Generation Job` заполняет или дорабатывает текст внутри этой выбранной страницы.

Роль редактора `AI Draft Editor` разрешает создавать, редактировать, публиковать, снимать с публикации и удалять `Page`, а также создавать `Generation Job`. Эта роль не предназначена для VPS, Docker, GitHub Actions, `.env`, API tokens, схем Strapi и серверных snapshot.

Если вы не разработчик, вам нужны только разделы “Вариант 0”, “Вариант 1” и “Вариант 1А”. Команды ниже относятся к технической проверке оператором.

Редактор не должен создавать новую страницу через код, VPS, Docker или Git. Для обычной страницы достаточно Strapi:

```text
Content Manager -> Page -> Create new entry
```

## Вариант 0. Новая страница по готовому макету + AI

Используйте этот вариант для большинства новых промо, брендовых и ресурсных страниц.

Коротко: экран `Generation Job` не создает новую страницу сам по себе. Он заполняет или дорабатывает уже выбранную `Page`. Если вы хотите новый URL, сначала создайте `Page`, потом запускайте `Generation Job`.

Для первой версии новой страницы проще не собирать блоки вручную с нуля, а взять подходящий макет:

- нужна страница как `/solutions/upsell` - создайте новую `Page` с таким же типом и набором блоков, затем попросите AI заменить текст под новую тему;
- нужна страница как `/for/government/real-estate` - создайте новую `Page` по этому же семейному макету и только потом заполняйте ее через AI;
- нужна простая статья/гайд - создайте `Page` с `page_kind = resource` и ресурсным набором блоков.

Если кнопки “Duplicate” в Strapi нет или вы не уверены, какие блоки нужны, не пытайтесь собрать сложный макет наугад. Создайте задачу техническому оператору: “подготовить Page-каркас по примеру `<URL примера>` для нового route `<новый URL>`”. AI должен менять текст внутри готового макета, а не придумывать новый порядок блоков.

### Шаги в Strapi

1. Откройте `Content Manager -> Page`.
2. Если страница уже есть, найдите ее по `route_path` или `title`.
3. Если нужен новый URL, нажмите `Create new entry` и создайте `Page`: заполните `title`, `slug`, `route_path`, `page_kind`, `blueprint`, SEO и добавьте стартовые блоки в `sections`.
   - Для страницы “как у примера” используйте тот же `page_kind`, похожий `blueprint` и такой же порядок смысловых блоков.
   - Для `/channels/...`, `/industries/...`, `/integrations/...` и других каталоговых страниц не выбирайте `resource`, если это не настоящий гайд/статья.
4. Сохраните `Page`.
5. Откройте `Content Manager -> Generation Job`.
6. Нажмите `Create new entry`.
7. Заполните:
   - `title` - понятное название задачи.
   - `job_type = manual_request`.
   - `status = queued`.
   - `target_blueprint` - выберите тип страницы простыми словами:
     - `campaign` - промо, спецпроект, продающая страница;
     - `brand` - страница направления, категории или бренда;
     - `resource` - гайд, инструкция, справка.
     Этот пункт должен совпадать с `page_kind` выбранной `Page`. Если у Page `campaign`, здесь тоже `campaign`; если `resource`, здесь `resource`.
   - `target_page` - выбранная `Page`, которую AI должен заполнить.
   - `request_prompt` - что именно нужно сделать.
   - `requested_by` - кто поставил задачу, например `content`.
8. Если нужно, выберите категории-контекст:
   - `target_channels`;
   - `target_industries`;
   - `target_integrations`;
   - `target_solutions`;
   - `target_features`;
   - `target_business_types`;
   - `target_competitors`.
9. Если в relation-поле видно только несколько вариантов, начните печатать название внутри поля. Strapi подгрузит остальные варианты поиском.
10. Не нажимайте `Create a relation`, если не уверены, что надо создать новую сущность. Обычно лучше оставить поле пустым и написать контекст в `request_prompt`.
11. Нажмите `Save`.
12. После запуска генерации откройте связанную `Page`.
13. Посмотрите закрытый Astro preview.
14. Если результат хороший, поставьте `editorial_status = approved` и нажмите `Publish`.
15. Если результат плохой, не публикуйте. Создайте новый `Generation Job`, выберите эту же `Page` в `target_page` и напишите prompt на доработку.

Частая ошибка: выбрать в `target_blueprint` значение `resource`, а в `target_page` указать страницу вида `/channels/email/beauty`. Это не новая resource-страница, а существующая страница пересечения канала и отрасли. Для такой задачи либо выберите правильный blueprint этой Page, либо сначала создайте новую Page с `page_kind = resource`. Если сомневаетесь, помните простое правило: `campaign` = продаём, `brand` = объясняем направление, `resource` = пишем гайд.

### Примеры prompt для заполнения готового макета

```text
Заполни выбранную Page по макету страницы /solutions/upsell, но с новым контекстом: автоматизация повторных продаж через WhatsApp и Telegram.
Цель: показать, как CHATPLUS помогает возвращать клиентов после первой покупки или записи.
Сохрани текущий route_path, page_kind, порядок sections, block_type и variants.
Перепиши только тексты внутри существующих блоков: hero, преимущества, сценарии, steps, FAQ, internal links и final CTA.
CTA оставь на /demo. Пиши по-русски, без процентов, гарантий, цен и обещаний 24/7.
```

```text
Заполни выбранную Page по макету страницы /for/government/real-estate, но для контекста: частные клиники и запись пациентов.
Сохрани структуру исходного макета: hero, проблема, карточки сценариев, шаги, интеграции, FAQ, связанные страницы и финальный CTA.
Не добавляй новые блоки и не удаляй существующие. Не меняй route_path, page_kind, block_type и variants.
Пиши по-русски, конкретно для клиник: запись, перенос визита, напоминания, вопросы пациентов, передача заявки администратору.
```

```text
Собери текст для уже созданной resource Page по теме: как подключить WhatsApp к CRM без ручного копирования заявок.
Структуру Page не меняй. Заполни существующие блоки как гайд: что это решает, кому подходит, какие шаги внедрения, какие ошибки проверить, FAQ.
Пиши простым русским языком. Не используй неподтвержденные цифры, цены и обещания роста.
```

```text
Сделай черновик страницы про Telegram для онлайн-школ.
Цель: показать, как CHATPLUS помогает отвечать ученикам и собирать заявки.
Заполни уже существующие блоки выбранной Page: hero, карточки, steps, FAQ и финальный CTA на /demo.
Пиши по-русски, без выдуманных цифр и без обещаний, которые нельзя проверить.
Не меняй route_path, page_kind, порядок sections, block_type и variants.
```

```text
Заполни выбранную campaign Page про WhatsApp для салонов красоты.
Цель: показать, как запись через мессенджеры помогает не терять заявки и быстрее передавать их администратору.
В hero, карточках, steps и FAQ используй ситуации: запись на услугу, перенос визита, напоминание, вопрос о цене, передача заявки в CRM.
CTA оставь на /demo. Пиши по-русски, без процентов, гарантий и обещаний 24/7.
Сохрани текущий макет Page и не добавляй новые блоки.
```

```text
Заполни выбранную resource Page как понятный гайд для редактора: как проверить AI-ответ перед отправкой клиенту.
Сделай текст спокойным и практическим: что смотреть в preview, какие ошибки искать, когда отправлять страницу на доработку.
FAQ должен отвечать на реальные вопросы: что делать с плохим текстом, как убрать обещания, когда публиковать.
Не меняй route_path и структуру блоков.
```

```text
Доработай выбранную Page после preview.
Проблемы: hero слишком общий, карточки похожи друг на друга, FAQ не отвечает на вопросы клиента.
Перепиши только тексты внутри существующих hero, cards-grid и faq.
Не меняй порядок блоков, block_type, variants, breadcrumbs и CTA-ссылки.
Оставь страницу черновиком для повторной проверки.
```

```text
Заполни выбранную brand Page про направление "Автоматизация заявок".
Покажи, для кого это направление: салоны, клиники, онлайн-школы и сервисные компании.
Не делай свободный лендинг. Используй текущие блоки выбранной Page и сохрани их порядок.
В тексте избегай "лучший", "мгновенно", процентов и точных сроков.
```

## Вариант 1. Собрать новую страницу руками в Page

Используйте этот вариант, если нужно самому собрать страницу в Strapi без AI или подготовить каркас для последующего AI-заполнения.

### Шаги в Strapi

1. Откройте `Content Manager -> Page`.
2. Нажмите `Create new entry`.
3. Заполните:
   - `title` — внутреннее название.
   - `slug` — короткий ключ, например `spring-promo`.
   - `route_path` — публичный адрес, например `/spring-promo`.
   - `page_kind` — тип страницы.
   - `blueprint` — стартовая схема страницы.
   - `seo_title` — title для поисковиков.
   - `seo_description` — description для поисковиков.
4. Соберите страницу из блоков в `sections`.
   - Нажмите `Add component` внутри `sections`.
   - Выберите только уже существующий тип блока.
   - Для обычного лендинга чаще всего нужны: `hero`, `cards-grid`, `rich-text`, `steps`, `faq`, `internal-links`, `final-cta`.
   - Новый тип блока через Strapi не создается. Если такого блока нет в списке, нужна техническая задача: schema + renderer + tests + docs.
5. Заполните настройки меню и sitemap, если они нужны.
6. Поставьте `editorial_status = approved`.
7. Нажмите `Publish`.

Новый route не требует отдельного `.astro` файла. Его подхватит общий page-layer после публикации и rebuild/deploy текущего production flow.

Для новой native-страницы не включайте `migration_ready`: она станет видимой после `Publish` и `editorial_status = approved`. `migration_ready` нужен только для старых URL, где мы защищаем старый макет.

Если после публикации страница не появилась сразу, не заходите на сервер. Передайте техническому оператору `route_path`, например `/spring-promo`, и попросите проверить rebuild/deploy.

## Вариант 1А. Подготовить каркас по похожей странице

Это самый безопасный способ для страниц “сделать как эта, но про другую тему”.

1. Найдите пример публичной страницы, например `/solutions/upsell` или `/for/government/real-estate`.
2. Откройте в Strapi соответствующую запись в `Content Manager -> Page`.
3. Создайте новую `Page` для нового URL.
4. Перенесите в новую `Page` тот же тип страницы и такой же порядок блоков в `sections`.
5. Замените только route, title и SEO под новую тему.
6. Нажмите `Save`, но не `Publish`.
7. Создайте `Generation Job`, выберите эту новую `Page` в `target_page` и попросите AI заполнить текст “по макету страницы-примера”.
8. Проверьте preview. Если макет отличается от примера или блоки пустые, не публикуйте.

## Вариант 2. Перенос существующей старой страницы

Используйте этот вариант, если URL уже существует: `/pricing`, `/partnership`, `/features`, `/compare/respond-io` и похожие.

### Почему тут осторожнее

У старой страницы уже есть свой макет. Поэтому одной публикации в Strapi недостаточно. Сначала нужно убедиться, что новая запись сохранила:

- hero;
- CTA;
- таблицы;
- карточки;
- FAQ;
- внутренние ссылки;
- SEO;
- старую family-структуру.

### Правило показа старого route

Старая страница переключается на `page_v2` только если одновременно выполнено:

- запись опубликована;
- `editorial_status = approved`;
- `migration_ready = true`;
- `parity_status = approved`.

Если хотя бы одно условие не выполнено, сайт показывает старый fallback.

## Вариант 3. Каталоговая или SEO-страница

Каталожные страницы тоже материализуются в `page_v2`, но факты остаются в сущностях:

- `channel`;
- `industry`;
- `integration`;
- `solution`;
- `feature`;
- `business_type`;
- `competitor`.

Это значит:

- сущность хранит факты;
- `page_v2` хранит публичную страницу, блоки, SEO, ссылки и route.

Если нужно добавить новый канал, отрасль, интеграцию, сценарий, функцию, тип бизнеса или конкурента, создайте запись в соответствующем справочнике Strapi или дайте AI предложить ее в `run_report.proposed_entities`. AI-предложения не применяются молча: задача получает `status = needs_entity_review`, оператор проверяет дубли/slug/описание и подтверждает создание черновика. Справочник сам по себе не заменяет публичную страницу и не отменяет проверку preview. Подробно: [Справочники: каналы, отрасли, интеграции и страницы по ним](entity-catalog-editor-workflow.md).

## Как выбрать `page_kind`

| Если нужна страница | Используйте |
| --- | --- |
| Обычный лендинг | `landing` |
| Промо или спецстраница | `campaign` |
| Страница компании, медиа, команды | `brand` |
| Документация, блог, помощь | `resource` |
| Корень каталога | `directory` |
| Карточка сущности | `entity_detail` |
| Пересечение сущностей | `entity_intersection` |
| Сравнение | `comparison` |
| Служебная страница | `system` |

## Минимальный набор перед публикацией

Перед `Publish` проверьте:

- `route_path` заполнен и начинается с `/`;
- `seo_title` заполнен;
- `seo_description` заполнен;
- есть хотя бы один содержательный блок в `sections`;
- CTA ведет на рабочий URL;
- internal links не пустые, если блок добавлен;
- `show_in_sitemap` включен только для страниц, которые нужно индексировать.

## Что делать после создания

Для редактора:

1. Откройте новый URL на публичном сайте.
2. Проверьте заголовок, CTA, ссылки, FAQ, SEO-смысл и отсутствие тестового текста.
3. Если страница не открылась или выглядит плохо, передайте техническому оператору `route_path`.

Локально или на сервере технический оператор должен проверить:

```powershell
npm.cmd --prefix portal run build
npm.cmd run page-v2:data-quality -- --problems --json
npm.cmd run page-v2:rendered-coverage -- --problems --json
```

Если отчеты пустые, страница не потеряла обязательный контент.

## Как удалить страницу

Если страницу нужно временно убрать с сайта, используйте `Unpublish`. Это безопаснее удаления: запись останется в Strapi, и ее можно будет поправить или вернуть.

Если страница тестовая, ошибочная, дубль или ее удаление согласовано:

1. Откройте `Content Manager -> Page`.
2. Найдите страницу по `route_path` или `title`.
3. Если страница опубликована, сначала нажмите `Unpublish`.
4. Проверьте, что это не старая важная страница сайта и не route, который нужен в навигации, sitemap или внутренним ссылкам.
5. Откройте меню записи и нажмите `Delete`.

Не удаляйте старые перенесенные страницы вместо отключения `migration_ready`. Для старых URL безопаснее снять публикацию или выключить `migration_ready`, чтобы сайт вернулся на старый fallback.

## Что нельзя делать

- Не создавайте новые ручные страницы в legacy-моделях.
- Не включайте `migration_ready` у старого маршрута без проверки макета.
- Не удаляйте старый `.astro` wrapper на этом этапе.
- Не переносите страницу в неподходящий generic-блок, если старый макет требует отдельный блок или variant.
