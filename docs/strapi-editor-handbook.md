# Понятная инструкция для редактора Strapi

Этот документ написан для человека, который не работает с кодом и хочет управлять сайтом через Strapi.

Если вы открыли Strapi впервые, начните с короткой карты интерфейса: [Карта интерфейса Strapi](strapi-ui-map.md).

Если нужно не просто понять поля, а увидеть примеры заполнения страниц, используйте: [Рецепты заполнения страниц](strapi-page-recipes.md).

## Главное для редактора

Если вы меняете контент, не заходите на сервер и не запускайте команды. Рабочее место редактора - только Strapi:

```text
Content Manager -> Page
```

Рабочая роль для обычного редактора называется `AI Draft Editor`. Логины, email, пароли и другие данные конкретных пользователей не хранятся в этой документации и Git.

С этой ролью можно:

- создавать новые `Page`;
- редактировать существующие `Page`;
- удалять `Page`, если это тестовая или согласованная к удалению страница;
- публиковать и снимать с публикации проверенные страницы;
- создавать и редактировать `Generation Job` для AI-заполнения выбранной страницы;
- читать справочники `Channel`, `Industry`, `Integration`, `Solution`, `Feature`, `Business Type`, `Competitor`.

С этой ролью нельзя и не нужно:

- заходить на VPS, в Docker, терминал, GitHub Actions или `.env`;
- менять Strapi-схемы, Content-Type Builder, API tokens, роли и настройки сервера;
- массово импортировать или экспортировать snapshot;
- менять справочники и системные поля без отдельного согласования;
- менять safety-gate поля старых URL: `migration_ready`, `parity_status`, `legacy_template_family`, `legacy_layout_signature`, `parity_notes`;
- редактировать `run_report` у `Generation Job`: его заполняет runner, редактор только читает результат.

Справочники `Channel`, `Industry`, `Integration`, `Solution`, `Feature`, `Business Type` и `Competitor` - это не редактор страниц. В них хранится короткая карточка сущности и технические данные для материализации страниц. Старые поля вроде `icon`, `emoji`, `h1`, `hero_*`, `seo_*`, `roi_*`, `faq`, `sticky_cta_*` и `content` не являются местом, где нужно собирать страницу вручную. Нормальная работа с публичной страницей идет через `Content Manager -> Page`.

В справочниках специально видны только короткие поля:

- `Business Type`, `Channel`, `Feature`: `slug`, `name`, `description`;
- `Industry`, `Solution`: `slug`, `name`, `description`, `pain`, `solution`;
- `Integration`: `slug`, `name`, `category`, `description`;
- `Competitor`: `slug`, `name`, `price`, `our_price`.

Это не значит, что остальные данные удалены. Они скрыты из формы редактора, но остаются в базе и snapshot для старых страниц, импорта и renderer logic. Если нужно поменять видимый текст на сайте, ищите `Page` по `route_path`; если нужно добавить новую сущность для AI-контекста, заполните только короткие поля справочника.

Важно: `Delete` физически удаляет запись из Strapi. Если страницу просто нужно убрать с сайта, сначала используйте `Unpublish`. Удаляйте только новые тестовые страницы, дубли или страницы, удаление которых явно согласовано.

Для новых страниц и больших правок приоритетный путь - не собирать блоки вручную, а создать задачу для нейросети:

```text
Content Manager -> Generation Job
```

AI делает только черновик. Редактор проверяет результат в preview, при необходимости отправляет эту же страницу на доработку через новый `Generation Job`, и только потом публикует.

В записи `Page` в правой панели есть блок `PREVIEW`. Если preview настроен, кнопка открывает закрытый просмотр этой страницы на Astro. Если там написано `Set up preview` и кнопка ведет в документацию Strapi, это не действие для редактора: preview не настроен на сервере или отсутствует `PREVIEW_TOKEN`. Сообщите разработчику, страницу при этом можно продолжать редактировать и сохранять, но публиковать лучше после нормальной проверки preview.

Что можно делать самому:

- менять тексты и ссылки в `sections`;
- добавлять, удалять и переставлять блоки;
- менять SEO-поля;
- включать страницу в меню или sitemap;
- создавать новую страницу через `Create new entry`;
- сохранять и публиковать проверенный контент.

Что не нужно делать редактору:

- подключаться к VPS;
- открывать Docker или терминал;
- делать `git pull`, `npm run build` или deploy;
- импортировать Strapi snapshot;
- менять `.env`, токены и секреты.

Если после правки страница выглядит плохо, это не задача для сервера. Сначала сохраните route страницы, например `/pricing`, и следуйте разделу [Что делать, если видите странный контент](#что-делать-если-видите-странный-контент).

## Что такое Page

`Page` в Strapi - это одна публичная страница сайта.

Примеры:

- `/pricing` - страница цен.
- `/promo` - промо-страница.
- `/compare/respond-io` - страница сравнения.
- `/channels/email/amocrm` - страница пересечения канала и интеграции.

Техническое имя этой сущности в коде - `page_v2`, но редактору это не важно. В интерфейсе Strapi ищите и редактируйте `Page`.

## Где сейчас работать

- публичный сайт: `https://astro.integromat.ru`
- админка Strapi: `https://strapi.integromat.ru/admin`
- основной раздел для работы: `Content Manager -> Page`

Если вы меняете только контент, вам не нужны Git, npm, Docker и команды терминала.

## Где найти страницу

1. Откройте Strapi admin.
2. Слева нажмите `Content Manager`.
3. Откройте коллекцию `Page`.
4. В поиске введите адрес страницы, например `/pricing`.
5. Откройте найденную запись.

Если вы не знаете точный адрес, ищите по `title`.

## Какие поля важны

| Поле | Что означает | Когда менять |
| --- | --- | --- |
| `title` | внутреннее название страницы | можно менять для удобства |
| `route_path` | публичный адрес страницы | менять осторожно, это URL |
| `page_kind` | тип страницы: landing, comparison, resource и т.д. | при создании новой страницы |
| `blueprint` | набор правил для блоков | при создании или смене типа страницы |
| `sections` | блоки страницы в нужном порядке | основное место редактирования |
| `seo_title` | title для поисковиков | перед публикацией обязательно |
| `seo_description` | description для поисковиков | перед публикацией обязательно |
| `show_in_header` | показывать в верхнем меню | если нужна ссылка в шапке |
| `show_in_footer` | показывать в футере | если нужна ссылка внизу |
| `show_in_sitemap` | показывать в sitemap | почти всегда включено для публичных страниц |
| `nav_label` | текст ссылки в меню | если страница есть в навигации |
| `nav_group` | группа меню | чтобы ссылка попала в нужную колонку |
| `editorial_status` | draft, review, approved, archived | перед publish ставьте `approved` |

## Какие поля лучше не трогать без разработчика

Эти поля защищают старые страницы от поломки макета:

- `migration_ready`
- `parity_status`
- `legacy_template_family`
- `legacy_layout_signature`
- `parity_notes`
- `source_mode`
- `generation_mode`
- `human_review_required`

Если случайно включить `migration_ready` на старой странице без проверки, сайт может показать не тот макет. Если страница выглядит плохо, выключите `migration_ready` и сообщите route разработчику.

## Как изменить текст на странице

1. Откройте нужную `Page`.
2. Найдите поле `sections`.
3. Раскройте нужный блок.
4. Измените текстовые поля.
5. Нажмите `Save`.
6. Проверьте preview или локальную страницу.
7. Если всё хорошо, поставьте `editorial_status = approved`.
8. Нажмите `Publish`.

## Как добавить новый блок

1. Откройте страницу.
2. В поле `sections` нажмите `Add component`.
3. Выберите блок.
4. Заполните поля блока.
5. Перетащите блок в нужное место.
6. Нажмите `Save`.
7. Проверьте страницу перед publish.

Чаще всего используются:

- `hero` - первый экран страницы.
- `rich-text` - обычный текст.
- `cards-grid` - карточки преимуществ, сценариев или материалов.
- `feature-list` - список возможностей.
- `steps` - шаги процесса.
- `faq` - частые вопросы.
- `comparison-table` - таблица сравнения.
- `pricing-plans` - тарифы.
- `before-after` - блок "до / после".
- `internal-links` - ссылки на соседние страницы.
- `final-cta` - финальный призыв к действию.

## Как создать новую страницу

1. В коллекции `Page` нажмите `Create new entry`.
2. Заполните `title`.
3. Заполните `slug`, например `new-campaign`.
4. Заполните `route_path`, например `/new-campaign`.
5. Выберите `page_kind`.
6. Выберите `blueprint`.
7. Заполните `seo_title` и `seo_description`.
8. Добавьте блоки в `sections`.
9. Если нужна навигация, заполните `show_in_header`, `show_in_footer`, `nav_group`, `nav_label`, `nav_order`.
10. Если страница должна быть в sitemap, включите `show_in_sitemap`.
11. Поставьте `editorial_status = approved`.
12. Нажмите `Publish`.

Для новой страницы обычно не нужно трогать `migration_ready` и `parity_status`.

После публикации сайт пересобирается текущим publish flow. Если изменения не появились сразу, сообщите оператору route страницы, например `/new-campaign`.

Важно: preview и публичная страница обновляются не одинаково. Preview показывает свежий контент из Strapi почти сразу. Публичный сайт `https://astro.integromat.ru/...` - это статическая сборка Astro, поэтому после `Publish` нужно дождаться автоматической пересборки. Обычно это занимает несколько минут. Если в preview новый блок виден, а на публичном URL его нет, не добавляйте блок второй раз: передайте оператору route страницы и скажите, что preview обновился, а публичная сборка еще нет.

## Как убрать страницу с сайта

Безопасный порядок:

1. Если страницу нужно временно скрыть, откройте `Page` и нажмите `Unpublish`.
2. Проверьте, что страница больше не должна быть публичной.
3. Если это тестовая, ошибочная или явно согласованная к удалению страница, откройте меню записи и нажмите `Delete`.
4. Не удаляйте старые важные страницы сайта без согласования. Для них чаще нужен `Unpublish` или отключение `migration_ready`, а не физическое удаление.

Для новой страницы:

1. Откройте страницу.
2. Нажмите `Unpublish`.

Для старой перенесённой страницы:

1. Откройте страницу.
2. Выключите `migration_ready`.
3. Сохраните.

Так сайт вернётся к legacy fallback, если он есть.

## Как понять, что страница готова

Страница готова, если:

- есть нормальный `route_path`;
- заполнены `seo_title` и `seo_description`;
- есть хотя бы один смысловой блок в `sections`;
- все CTA ведут на правильные ссылки;
- FAQ не содержит тестовых вопросов;
- `editorial_status = approved`;
- страница открывается в браузере и выглядит нормально.

## Что делать, если видите странный контент

Примеры плохих признаков:

- текст на английском там, где нужен русский;
- вопрос вроде `Can this page be edited in Strapi?`;
- пустая таблица;
- дубль блока "соседние сравнения";
- блок появился два раза;
- старый макет стал слишком коротким или потерял секции.

Что сделать:

1. Не публикуйте страницу дальше.
2. Запишите `route_path`, например `/compare/respond-io`.
3. Проверьте, какой блок содержит плохой текст.
4. Если это старая страница, выключите `migration_ready`, нажмите `Save` и проверьте публичный сайт.
5. Если это новая страница без старого fallback, нажмите `Unpublish`.
6. Передайте route и название блока разработчику или техническому оператору.

Не подключайтесь к серверу и не запускайте deploy из-за плохого текста или блока. Для редактора правильный откат делается через Strapi.

## Что насчет AI

Сейчас для крупной переработки текста удобнее использовать AI-контур через `Generation Job`. Для новой страницы сначала нужна `Page` с правильным макетом, а уже потом AI заполняет текст внутри выбранных блоков.

Минимальный процесс:

1. Откройте `Content Manager -> Generation Job`.
2. Нажмите `Create new entry`.
3. Заполните `title`, `job_type = manual_request`, `target_blueprint`, `target_page`, `request_prompt`, `requested_by`.
4. При необходимости выберите категории: channels, industries, integrations, solutions, features, business types, competitors.
5. `target_page` обязателен всегда: выберите страницу, которую надо заполнить или доработать.
6. Оставьте `status = queued`.
7. После генерации откройте связанную `Page`, посмотрите preview и проверьте результат.

Relation-поля с категориями могут выглядеть пустыми или показывать только первые варианты. Чтобы найти остальные, кликните в поле `Add or create a relation` и начните печатать часть названия. Например: `whatsapp`, `telegram`, `amo`, `bitrix`, `мед`, `салон`. Если нужной записи нет, не создавайте новую случайно из этого выпадающего поля: оставьте поле пустым и опишите нужный контекст в `request_prompt` или создайте запись через отдельный справочник.

Новые каналы, отрасли, интеграции, сценарии, функции, типы бизнеса и конкурентов можно добавлять вручную в `Content Manager` через коллекции `Channel`, `Industry`, `Integration`, `Solution`, `Feature`, `Business Type`, `Competitor`, если это отдельно согласовано. В обычной редакторской работе эти коллекции лучше не трогать: у них есть технические поля и старые поля совместимости. AI также может предложить недостающую запись в `run_report.proposed_entities`, но она не создается и не публикуется молча: задача получает `status = needs_entity_review`, затем оператор подтверждает создание черновика. Такая запись дает AI контекст, но публичная страница по ней создается и проверяется отдельно как `Page`. Полный порядок: [Справочники: каналы, отрасли, интеграции и страницы по ним](entity-catalog-editor-workflow.md).

Если результат не нравится, не публикуйте страницу. Создайте новый `Generation Job`, выберите эту же страницу в `target_page` и напишите, что исправить. Нейросеть получит текущий черновик как контекст и сохранит его `route_path`, `page_kind`, порядок блоков, `block_type` и `variant`. Если AI попытается добавить, удалить или переставить блоки, runner отклонит результат.

## Если AI сделал черновик, но его нужно улучшить

Есть два нормальных варианта.

Первый вариант - отправить эту же страницу на доработку через новый prompt. Это удобно, если нужно переписать много текста: hero, карточки, FAQ, CTA или весь тон страницы.

1. Не нажимайте `Publish`.
2. Откройте `Content Manager -> Generation Job`.
3. Нажмите `Create new entry`.
4. В `target_page` выберите ту же `Page`, которую уже смотрели в preview.
5. В `target_blueprint` выберите тот же тип, что у страницы в `page_kind`.
6. В `request_prompt` напишите, что именно исправить.
7. Оставьте `status = queued`.
8. После запуска снова откройте preview этой же страницы.

Пишите prompt конкретно. Не "сделай лучше", а что именно не так:

```text
Доработай выбранную Page после preview.
Сохрани route_path, page_kind, порядок sections, block_type и variants.
Hero слишком общий - сделай его конкретнее для салонов красоты.
FAQ слабый - добавь вопросы про запись, перенос визита, напоминания и ответы в WhatsApp.
CTA оставь на /demo.
Не добавляй новые блоки, не меняй breadcrumbs, не публикуй страницу.
```

Еще примеры prompt:

```text
Доработай выбранную Page.
Сделай текст спокойнее и полезнее, меньше рекламы.
Убери гарантии, проценты, "мгновенно", "лучший", "рост продаж" и точные сроки.
Сохрани структуру page_v2 и оставь страницу draft/review.
```

```text
Доработай выбранную Page под отрасль: медицинская клиника.
Сохрани текущий макет и все variants.
В hero, cards-grid, steps и FAQ опиши запись пациента, уточнение услуги, передачу заявки администратору и проверку AI-ответа человеком.
Не придумывай цены, гарантии и новые интеграции.
```

```text
Доработай выбранную Page.
Улучши только SEO title, SEO description и FAQ.
Основной текст, route_path, порядок блоков, block_type и variants не меняй.
FAQ сделай практическим: подключение, CRM, права доступа, ручная проверка AI-ответов.
```

```text
Доработай выбранную Page после preview.
Проблемы: второй cards-grid непонятный, steps слишком длинные, final CTA повторяет hero.
Сохрани все существующие блоки в том же порядке.
Сделай карточки короче, steps по 3-4 строки, final CTA конкретнее.
```

Второй вариант - поправить руками в `Page -> sections`. Это лучше, если правка маленькая:

- заменить одну фразу;
- укоротить заголовок;
- поправить ссылку кнопки;
- убрать лишнее обещание;
- переписать один вопрос FAQ;
- поправить SEO title или description.

Порядок ручной правки:

1. Откройте `Content Manager -> Page`.
2. Найдите страницу по `route_path` или `title`.
3. Раскройте поле `sections`.
4. Откройте нужный блок: `hero`, `cards-grid`, `steps`, `faq`, `internal-links`, `final-cta`.
5. Исправьте текст или ссылку.
6. Нажмите `Save`.
7. Проверьте preview.
8. Публикуйте только после проверки.

Руками лучше не трогать технические поля: `page_kind`, `block_type`, `variant`, `migration_ready`, `parity_status`, `legacy_template_family`, `legacy_layout_signature`. Если кажется, что нужно менять именно их, это уже задача для технического оператора, а не обычная контент-правка.

Даже после включения AI редактор всё равно будет проверять:

- адрес страницы;
- SEO;
- выбранные блоки;
- тексты;
- ссылки;
- sitemap и навигацию.
- что каркас страницы не изменился.

AI не должен включать `migration_ready` для старых страниц без проверки.

См. также: [AI-черновик: проверка до публикации](ai-draft-preview-workflow.md).
