# Справочники: как добавлять каналы, отрасли, интеграции и страницы по ним

Этот документ для редактора Strapi. Если вы меняете контент, не заходите на VPS, в Docker, терминал, GitHub Actions и `.env`: работайте только в Strapi.

## Короткий ответ

Да, новые записи можно создавать во всех справочниках:

- `Channel` - каналы связи: WhatsApp, Telegram, Email.
- `Industry` - отрасли: медицина, недвижимость, салоны, образование.
- `Integration` - интеграции: amoCRM, Bitrix24, RetailCRM.
- `Solution` - сценарии: продажи, поддержка, заявки.
- `Feature` - функции продукта: AI-ответы, аналитика, виджеты.
- `Business Type` - тип бизнеса: клиника, агентство, интернет-магазин.
- `Competitor` - конкуренты для сравнений.

Но важно различать две вещи:

- Запись в справочнике - это факт и контекст для AI.
- Публичная страница - это отдельная `Page`, которую надо проверить в preview и опубликовать.

Новая запись в справочнике помогает нейросети писать точнее, но сама по себе не означает, что на сайте сразу появилась хорошая публичная SEO-страница.

Важно: `Generation Job` не должен молча плодить новые справочники. Если AI понимает, что для prompt нужна новая сущность, он кладет предложение в `run_report.proposed_entities` и переводит задачу в `status = needs_entity_review`. После проверки оператор может подтвердить предложения и перезапустить runner с `--approve-entity-proposals`: тогда записи создаются как черновики `managed/frozen`, привязываются к `Page`, и только потом создается черновик страницы.

## Безопасный способ добавить новый вариант

1. Откройте `Content Manager`.
2. Откройте нужный справочник: `Channel`, `Industry`, `Integration`, `Solution`, `Feature`, `Business Type` или `Competitor`.
3. Сначала найдите запись поиском, чтобы не создать дубль.
4. Если записи нет, нажмите `Create new entry`.
5. Заполните минимум:
   - `name` - понятное название;
   - `slug` - короткий адресный ключ латиницей, например `beauty-salons`;
   - `description` - 1-3 предложения, что это за сущность и зачем она нужна.
6. Если есть SEO-поля, заполните `seo_title` и `seo_description`.
7. Нажмите `Save`.
8. Нажмите `Publish`, если запись готова к использованию.

После публикации запись можно выбирать в `Generation Job` как категорию-контекст. Если запись предложила нейросеть, все равно сначала проверьте название, slug и описание в `run_report`.

## Как работает AI-предложение нового справочника

1. Редактор создает `Generation Job` и пишет prompt, например: `Сделай страницу про WhatsApp для салонов красоты`.
2. Если `target_industries` не выбран и AI считает, что нужна новая отрасль, он добавляет ее в `proposed_entities.industries`.
3. Если такой записи нет, runner не создает `Page` сразу, а ставит `status = needs_entity_review`.
4. Редактор или оператор открывает `run_report` и проверяет:
   - `name` - без дублей и странных формулировок;
   - `slug` - короткий латинский ключ;
   - `description` - нормальное описание без выдуманных фактов;
   - `reason` - почему AI предложил эту запись.
5. Если предложение подходит, оператор запускает задачу с подтверждением `--approve-entity-proposals`.
6. Runner создает недостающие справочники как черновики, привязывает их к задаче и создает черновик `Page`.

AI-предложение не публикует новый справочник автоматически. Это специально: публикация новой отрасли, канала или интеграции может создать дополнительные публичные catalog/intersection routes. Перед публикацией новой записи нужно проверить, что по ней есть нормальная `Page`, внутренние ссылки не ломаются, и локальный `portal build` проходит без orphan pages.

Если AI предложил сущность, которая уже есть в справочнике с таким же `slug` или `name`, runner не создает дубль. Он записывает ее в `duplicate_entities`/`resolved_existing_entities` и использует существующую запись как связь для `Page`.

Команда для оператора:

```powershell
npm.cmd run page-v2:generate -- --job-id=DOCUMENT_ID --approve-entity-proposals
```

Если предложение плохое, не подтверждайте его. Лучше поправить prompt или создать правильную запись вручную.

## Что не трогать

Не меняйте технические поля без оператора:

- `content_origin`
- `record_mode`
- `external_id`
- `import_batch_id`
- `last_imported_at`
- `sync_strategy`
- `manual_override_fields`
- `last_import_diff`
- `last_import_payload`

Эти поля нужны для импорта, синхронизации и защиты ручных правок. Ошибка здесь может привести к перезаписи контента при следующем переносе snapshot.

## Как связать новый справочник с новой страницей

Самый удобный путь:

1. Создайте или найдите запись в справочнике.
2. Откройте `Content Manager -> Generation Job`.
3. Создайте задачу:
   - `job_type = manual_request`;
   - `status = queued`;
   - `target_blueprint = campaign`, `brand` или `resource`;
   - `request_prompt` - что именно должна сделать нейросеть.
4. В relation-поле выберите нужную запись:
   - `target_channels`;
   - `target_industries`;
   - `target_integrations`;
   - `target_solutions`;
   - `target_features`;
   - `target_business_types`;
   - `target_competitors`.
5. После генерации откройте созданную `Page`.
6. Посмотрите Astro preview.
7. Если результат хороший, поставьте `editorial_status = approved` и нажмите `Publish`.
8. Если результат слабый, не публикуйте. Создайте новый `Generation Job`, выберите эту же страницу в `target_page` и напишите prompt на доработку.

## Если нужного варианта нет в выпадающем списке

В relation-полях Strapi сначала показывает только несколько записей. Это нормально.

Что делать:

1. Кликните в `Add or create a relation`.
2. Начните печатать название: `whatsapp`, `telegram`, `amo`, `bitrix`, `салон`, `медицина`.
3. Если запись нашлась, выберите ее.
4. Если запись не нашлась, не нажимайте `Create a relation` случайно.
5. Лучше откройте нужный справочник через левое меню и создайте запись там.

Кнопка `Create a relation` допустима только если вы точно понимаете, какую сущность создаете. Для редактора безопаснее создавать справочник из его собственной коллекции, а не из выпадающего поля внутри `Generation Job`.

## Когда можно оставить категорию пустой

Если нужна разовая страница, категорию можно не создавать. Просто опишите контекст в `request_prompt`. В таком режиме AI использует текст из prompt. Если он предложит новый справочник, подтверждайте его только когда тема будет использоваться повторно.

Пример:

```text
Сделай черновик страницы про WhatsApp для салонов красоты.
Если отдельной отрасли "салоны красоты" в справочнике нет, используй это как текстовый контекст из prompt.
Не выдумывай цифры. CTA ведет на /demo.
```

Создавать новую запись в справочнике стоит тогда, когда тема будет использоваться много раз: для страниц, внутренних ссылок, фильтрации, навигации или будущих AI-задач.

## Как появляются страницы по новым справочникам

Есть три уровня:

1. Запись в справочнике создана и, если она должна быть публичной, опубликована после проверки.
2. По ней создана или доработана `Page`.
3. Сайт пересобран и получил актуальный Strapi snapshot.

На локалке это проверяет оператор через build и preview. На сервере одного Git push недостаточно: если менялся Strapi-контент, нужен content snapshot/import и rebuild portal.

Редактору это делать не нужно. Редактор создает и проверяет контент в Strapi, а если публичная страница не появилась после публикации, передает оператору `route_path` или название новой записи.

## Примеры prompt

Новая страница по отрасли:

```text
Сделай черновик страницы про CHATPLUS для стоматологий.
Цель: показать, как клиника обрабатывает обращения из мессенджеров, не теряет заявки и быстрее отвечает пациентам.
Нужны hero, 4 преимущества, сценарии использования, FAQ и CTA на /demo.
Пиши по-русски, без выдуманных цифр.
```

Новая страница по интеграции:

```text
Сделай черновик страницы про интеграцию CHATPLUS с Bitrix24.
Покажи пользу для отдела продаж: сообщения, заявки, история общения, контроль менеджеров.
Не обещай функции, которых нет в продукте.
CTA ведет на /demo.
```

Новая страница с AI-предложением недостающей категории:

```text
Сделай черновик страницы про Telegram для детских образовательных центров.
Если в справочнике нет отдельной отрасли "детские образовательные центры", предложи ее в proposed_entities.industries, но не создавай молча.
Цель страницы: показать, как CHATPLUS помогает отвечать родителям, собирать заявки на пробные занятия и не терять переписки.
Нужны hero, блок проблем, шаги внедрения, FAQ и CTA на /demo.
Пиши по-русски, без выдуманных цифр и без обещаний автоматической оплаты.
```

Страница по нескольким категориям:

```text
Сделай черновик campaign-страницы про связку WhatsApp + amoCRM для отдела продаж в недвижимости.
Используй выбранные категории как контекст: канал, интеграцию, отрасль и сценарий продаж.
Покажи путь заявки: клиент пишет в WhatsApp, менеджер видит диалог, заявка фиксируется в CRM, руководитель контролирует обработку.
Добавь сравнение "до / после", 5 частых вопросов и финальный CTA на /demo.
Не публикуй страницу.
```

Доработка существующей страницы:

```text
Доработай выбранную страницу.
Сохрани route и общий смысл.
Сделай первый экран конкретнее, добавь больше практических примеров для салонов красоты и расширь FAQ.
Не публикуй страницу.
```

SEO-усиление и FAQ без смены маршрута:

```text
Доработай выбранную страницу без смены route_path.
Усиль seo_title и seo_description, чтобы было понятно: CHATPLUS помогает обрабатывать сообщения клиентов из мессенджеров в одном окне.
Не меняй основной оффер и CTA.
Добавь FAQ с вопросами про внедрение, безопасность доступа, CRM и что делать, если каналов несколько.
Не придумывай тарифы, проценты и интеграции, которых нет в текущем контексте.
```
